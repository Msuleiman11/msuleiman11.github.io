Home SOC lab — Wazuh SIEM

Wazuh 4.14.7 · Ubuntu endpoint · bridged VirtualBox network

A Wazuh server and a monitored Linux endpoint on the same network, with a Windows host used as the attack source. Everything below was configured, attacked and investigated end to end.

  • SSH brute force — watched individual level 5 authentication failures escalate into a level 10 correlated brute-force detection once eight arrived inside two minutes. Same events, different conclusion.
  • File integrity monitoring — configured syscheck against a directory of my own, then traced modification, addition and deletion alerts back to before-and-after content hashes.
  • Breaking it — a single missing character in the agent config took the endpoint offline entirely. Diagnosed and fixed, and written up, because that failure is more instructive than a clean run.

Next: custom detection rules, so the alerting logic is mine rather than Wazuh's defaults — and Windows telemetry, which is the gap in the lab as it stands.

Project dissertation

Human-in-the-loop penetration testing framework

BSc Cybersecurity · University of Bedfordshire · 2026

A Flask, Jinja2 and SQLite application that puts a language model into a penetration testing workflow, with a mandatory accept, modify or reject decision before any suggested action can execute. Evaluated against Hack The Box targets, with automated reporting and CSV export.

The interesting problem wasn't capability. It was that the model was confidently wrong often enough that letting it act unsupervised was the actual risk. The first build let it run commands directly; it produced actions that went outside the defined scope, so I rebuilt it around a human gate rather than patching individual failures.
